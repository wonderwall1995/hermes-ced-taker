# 해설 파일의 약속 (controller ↔ testgate)

작성일: 2026-11-19. 상태: **사용자가 6장의 기본값을 확인했다.** testgate 쪽(시작 명령, 해설 파일 읽기)은 testgate 저장소의 브랜치 `feat/context-file`에 구현해 커밋했고 시험했다. **hermes-controller 쪽(해설 파일 쓰기, 시작 명령으로 실행)은 아직 없다.** 병합, 설치, 라이브 반영은 하지 않았다.

hermes-controller가 만든 CED 해설을 testgate에 넘기는 방법을 정한다. 두 프로젝트가 서로를 모르는 채 이 약속만 지키면 되게 한다.

## 1. 한눈에 보기

```
웹훅 라우트 (변경 없음)
   → testgate 필터   ... 요청을 requests/<배달ID>.json 으로 저장하고, "분석 시작 명령"을 실행한다
        → hermes-controller
             1) github-app에서 PR 정보를 한 번 가져온다
             2) ced-taker에게 해설을 만들게 한다 (기존 provide 명령)
             3) 해설을 requests/<배달ID>.context.json 으로 둔다        ← 이 문서의 약속
             4) testgate 래퍼를 실행한다
                  → 래퍼는 .context.json이 있으면 읽고, 없으면 지금처럼 동작한다
```

이 문서가 정하는 것은 두 가지이다.

- **A. 해설 파일**: 이름, 위치, 모양, 쓰는 방법, 읽는 방법, 실패했을 때.
- **B. 시작 명령**: testgate 필터가 분석을 시작할 때 실행하는 명령을 설정에서 읽게 하는 것.

## 2. 이미 정해진 것

- controller가 PR 정보를 한 번 가져와 ced-taker에만 준다. testgate는 지금처럼 자기가 따로 가져온다.
- 해설은 요청 파일 옆에 파일 하나로 둔다. 있으면 읽고, 없으면 지금처럼 동작한다.
- 웹훅 라우트는 그대로이고, 필터가 분석 시작 명령을 설정에서 읽는다.
- controller는 이 파이프라인 하나만 다룬다.
- 실패하면 해설 없이 testgate를 계속하고, 보고서 비고에 한 줄을 남긴다.

## 3. A. 해설 파일

### 3.1 위치와 이름

- 위치: testgate의 요청 파일과 같은 폴더(`<홈>/testgate/requests/`).
- 이름: `<배달ID>.context.json`. 요청 파일(`<배달ID>.json`)과 같은 배달 ID를 쓴다.
- 보관 정리는 따로 만들지 않는다. testgate의 정리 함수가 이 폴더의 모든 파일을 보관 기간(30일)이 지나면 지운다(소스에서 확인함). 해설 파일도 같이 지워진다.

### 3.2 모양

JSON, UTF-8. ced-taker의 `provide` 응답과 **같은 모양**이다. 그래서 controller는 ced-taker의 응답을 그대로 쓰면 된다.

```json
{
  "version": 1,
  "docs": [
    {"id": "ced:amount", "title": "CED 해설: amount", "text": "걸림: ...\n위치: ...\n\n(본문)"}
  ],
  "notices": ["현재 의도와 벗어난 상태: ..."]
}
```

| 필드 | 형식 | 설명 |
|---|---|---|
| `version` | 정수 | 1. 다르면 읽지 않는다. |
| `docs` | 배열 | `{id, title, text}` 문자열 세 개. 비어 있어도 된다. |
| `notices` | 배열(선택) | 보고서 비고에 한 줄씩 남길 짧은 글 |

- 알 수 없는 필드는 무시한다. 나중에 필드를 더해도 이 버전은 깨지지 않는다.
- testgate는 이 파일이 누구에게서 왔는지 모른다. "참고 문서 파일"일 뿐이다.

### 3.3 쓰는 쪽 (controller)

- 임시 이름에 쓴 뒤 최종 이름으로 바꾼다(testgate가 요청 파일을 쓰는 방식과 같다). 읽는 쪽이 반쯤 쓰인 파일을 볼 일이 없다.
- 권한은 600이다. 본문에 CED 설명이 들어 있다.
- **래퍼를 실행하기 전에** 쓴다. 래퍼가 시작된 뒤에 쓰면 읽는 시점과 겹칠 수 있다.
- 해설을 못 만들었어도 파일을 쓴다(3.5 참고).

### 3.4 읽는 쪽 (testgate 래퍼)

- 분석 직전에, 요청 파일과 같은 배달 ID의 해설 파일을 읽는다.
- **파일이 없으면 지금과 똑같이 동작한다.** controller를 쓰지 않는 환경이 그대로 동작해야 한다.
- 읽은 문서는 지금의 참고 문서와 똑같이 "신뢰하지 않는 데이터" 블록으로 프롬프트에 들어간다. 지시로 읽지 않는다.
- 제한: 문서 50건, 문서당 2만 자, 합계 6만 자, 안내 5건(각 300자). 넘으면 잘라 내고 비고에 한 줄을 남긴다.
- 파일이 깨졌거나(JSON 오류, 형식 오류, 버전 다름) 읽을 수 없으면 해설 없이 분석을 계속하고, 보고서 비고에 사유 코드 한 줄을 남긴다. 사유 코드는 `bad_output`, `unsupported_version`, `unreadable` 등이다.

### 3.5 해설을 못 만들었을 때

controller가 ced-taker를 실행하지 못했거나 시간이 초과되면, **문서가 빈 파일을 쓴다.** 비고에 한 줄이 남게 하기 위해서이다.

```json
{"version": 1, "docs": [], "notices": ["참고 문서 공급자가 응답하지 않아 해설 없이 분석함 (timeout)."]}
```

- 사유 코드는 `timeout`, `exit_code`, `bad_output`, `not_found` 등이다. 공급자가 쓴 오류 문장은 쓰지 않는다.
- 파일을 쓰지 않으면 testgate는 "해설이 없다"와 "해설을 만들려 했는데 실패했다"를 구분하지 못한다.

### 3.6 보고서에 보이는 것

testgate는 보고서의 "비고" 영역에 다음을 남긴다. "CED"라는 말은 testgate 코드에 없다. 제목은 파일이 준 글이다.

- 문서가 있을 때: `참고 문서 N건이 첨부됨: 제목, 제목, ...`(제목은 최대 5개, 나머지는 "외 N건")
- 안내가 있을 때: 안내를 한 줄씩. (예: 같은 컬럼명이 여러 제품에 있다는 경고)
- 해설 파일이 없을 때: 아무것도 남기지 않는다.

보고서(PR 코멘트)에 들어가는 글은 testgate의 이스케이프(멘션, HTML, 이미지·링크 문법)를 거치고, 맨 URL은 자동 링크가 되지 않게 깨뜨린다.

### 3.7 보안

- 해설 파일을 쓸 수 있는 사람은 요청 파일도 쓸 수 있는 사람이다. 같은 폴더, 같은 권한(600)이라 신뢰 범위가 같다.
- 파일 이름은 배달 ID로 정해지고, 배달 ID는 testgate가 이미 형식을 검사한다. 경로 구분자가 들어갈 수 없다.
- 문서 본문은 CED의 원문이다. 프롬프트에서 데이터로만 쓴다.

## 4. B. 시작 명령

- testgate 필터는 지금 분석 래퍼를 정해진 경로(`<홈>/testgate/testgate-run`)로 실행한다.
- **설정에서 시작 명령을 읽게 한다.** testgate 설정(`testgate.json`)의 항목에 명령(인자 목록)을 적는다. 필터는 그 명령에 **배달 ID를 마지막 인자로 붙여** 지금과 똑같이 백그라운드로 실행한다(표준 입출력을 닫고 새 세션으로).
- **설정이 없으면 지금과 똑같이 동작한다.** 기본값은 지금의 래퍼이다.
- 시작 명령을 controller로 지정하면: controller가 배달 ID로 요청 파일을 찾아 PR 정보를 가져오고, ced-taker를 실행하고, 해설 파일을 쓰고, **마지막에 testgate 래퍼를 실행한다.**
- testgate는 시작 명령이 무엇인지 모른다. 명령이 래퍼를 실행하지 않으면 분석이 일어나지 않는다. 이것은 명령의 책임이다.
- **controller는 어떤 오류가 나도 마지막에 testgate 래퍼를 실행해야 한다.** 해설을 못 만들었어도, PR 정보를 못 가져왔어도 래퍼는 실행한다(해설 없이). 그래야 분석이 조용히 사라지지 않는다.

## 5. 실패와 독립성

| 상황 | 동작 |
|---|---|
| controller를 쓰지 않는다(설정 없음) | testgate는 오늘과 똑같이 동작한다. |
| 시작 명령 파일이 없다(설정 오류) | 필터가 요청을 저장하기 전에 실패한다. 지금 래퍼가 없을 때와 같은 처리이다(종료 코드 1, 저장 안 함). |
| **controller가 래퍼를 실행하기 전에 죽는다**(강제 종료, 예상 밖 오류) | **분석도 실패 코멘트도 없이 요청만 남는다.** testgate의 "놓친 요청"(보고서도 실패 코멘트도 없는 건)과 같은 종류이다. controller가 모든 오류를 잡아 래퍼를 실행하게 해서 줄일 수 있지만, 프로세스가 강제로 끝나는 경우까지 막지는 못한다. |
| controller는 실행됐는데 ced-taker가 실패한다 | 해설 없이 분석한다. 비고에 사유 한 줄. |
| 해설 파일이 깨졌다 | 해설 없이 분석한다. 비고에 사유 한 줄. |
| testgate 없이 controller만 쓴다 | 해당 없음. controller는 testgate 래퍼를 부르는 것이 존재 이유이다. |
| ced-taker 없이 testgate만 쓴다 | 해설 파일이 없는 것과 같다. 오늘과 똑같다. |

## 6. 기본값으로 정한 것 (바꾸고 싶으면 알려 달라)

사용자에게 묻지 않고 정했다. 안쪽 규칙이기 때문이다.

1. 파일 이름은 `<배달ID>.context.json`이고 요청 파일 옆에 둔다.
2. 보고서 비고에 공급자의 이름표는 넣지 않는다. 해설 파일 하나에는 출처가 하나라서 필요가 없다.
3. 실패는 "문서가 빈 해설 파일 + 안내 한 줄"로 알린다.
4. controller가 testgate 래퍼의 위치를 아는 방법은 controller의 로컬 설정이다(Git 제외). 이 문서의 범위 밖이다.
5. 시작 명령의 설정 항목 이름은 구현할 때 정한다(`testgate.json`의 `analysis` 안).

## 7. 이 약속이 바꾸지 않는 것

- ced-taker: 변경 없음. `provide`의 응답이 그대로 해설 파일이 된다.
- github-app: 변경 없음.
- Hermes: 웹훅 라우트 변경 없음.

## 8. 아직 정하지 않은 것

- 위의 "controller가 래퍼 실행 전에 죽는 경우"를 어떻게 줄일지. 예를 들어 필터가 일정 시간 뒤에도 보고서가 없는 요청을 알아채는 감시자가 있다. testgate의 할 일 목록에 "감시자"가 이미 선택 항목으로 있다. 이번 약속의 범위에는 넣지 않았다.
- (정해짐) controller가 github-app에 서명할 키는 **기존 환경 변수를 그대로 읽는다**(변수 이름은 controller 설정에서 지정). github-app의 `.env`와 Hermes의 `.env`는 바꾸지 않는다. 필터가 띄운 프로세스가 Hermes의 환경을 물려받는다는 것은 코드로 짐작했을 뿐 **실제로 시험하지 못했다.**
- (정해짐) controller는 Python 표준 라이브러리와 unittest로 만든다(pnpm은 명령 단축용).
- 위의 약속이 문서에 적힌 대로 testgate의 기존 시험을 깨지 않는지는 구현할 때 확인한다.
